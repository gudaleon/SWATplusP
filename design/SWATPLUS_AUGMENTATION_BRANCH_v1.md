# SWAT+P — the augmented SWAT+ branch of the worked-example programme, version 1

Method: Researcher-led AI research. This branch was added by Alex's direction of 2026-11-19, given in the Lake of the Woods thread in the words "Or augment swat+.", and it is a first-class branch of the P-core worked-example programme, not an afterthought to it.

## The connection, stated plainly

**The other models in this programme supply the verified behaviour, and the SWAT+P phosphorus routines are the worked example that is checked against them case by case.**

The speciation examples in PHREEQC and CrunchTope establish, in computed numbers, what dissolved phosphorus actually consists of and when a soil water reaches mineral saturation. The Parsons example, which reimplements the reaction network of Zhou et al. (2023), establishes how a two-rate, capacity-limited retention core behaves as it fills. The BioRT-Flux-PIHM example establishes that a phosphorus reaction network of that kind runs at field scale in a reactive transport code. The RZWQM2-P example establishes how dissolved and particulate phosphorus reach tile drainage through macropores at a real field site. SWAT+P is then built from those verified behaviours, stage by stage, and it is tested against the same cases that the other codes run, so that every process the augmentation claims is a process that this programme has already executed somewhere it can be checked.

## The staged ladder, as designed in the Lake of the Woods proposal

The augmentation follows the five-stage ladder that the Lake of the Woods proposal already carries, and this branch changes none of its stages. The first stage changes no code: the stock routines run with parameters derived from measured soil profiles, through the RZWQM2-P derivation, instead of the shipped defaults. The second stage is the benchmark symptom audit of the stock routines, which tests the three structural symptoms that the source audit predicts, namely instantaneous-equilibrium sorption, the absence of a finite sorption capacity, and organic phosphorus mineralization that is slaved to the nitrogen cycle. The third stage replaces the sorption core alone with the two-rate, capacity-limited formulation, field-tested in BioRT-Flux-PIHM before it is implemented in SWAT+, with the stock routine retained as a switchable branch so that the two formulations can be run as a fork and reported per branch. The fourth stage gives organic phosphorus mineralization its own kinetic law in temperature and soil moisture and gives manure phosphorus its own pool behaviour. The fifth stage adds the transport pathways that the audit found missing, namely dissolved and particulate phosphorus through tile drains and macropores.

## The rules that bind the branch

The augmentation is kept outside any calibration, and it is frozen before any calibrated use, so that no calibrated parameter can quietly absorb a structural change and no structural change can be tuned to a fit. The stock routines under both values of the routine-selection flag, which is `sol_p_model` with default 0 for the Jones-lineage routine and 1 for the Vadas and White (2010) routine, are the control case for every augmented run, because a difference that cannot be shown against the stock code on the same inputs is not a result. The starting point for the code work is the SWAT+ source clone at `~/workspace/lake_of_the_woods/proposals/models/swatplus_src`, at commit `6f515368525e7d84089ae0f9d33f4c9115de5679`, together with the audit files `JONES1984_SWATPLUS_P_AUDIT_v1.md` and `JONES1984_RESEARCH_COMPLETION_v1.md`, and the augmented code will be developed as a separate branch of that clone so that the audited source of record is never modified in place. When any input to an augmented run changes, every dependent result is recomputed, and no claim about the augmented routine enters the paper until it has passed a hostile read against the control runs.

## What "worked" means for this branch, stage by stage

For the sorption core, the test cases are pool-level cases that any daily pool model can be asked to pass: a fertiliser pulse that must relax toward equilibrium at the fast rate first and the slow rate second, a long repeated-loading run that must show retention declining as the finite capacity fills and must show release when the porewater concentration falls below the equilibrium concentration, and a drawdown run that must show legacy release governed by the degree of saturation, none of which the stock routine can produce at any parameter values, which is precisely why they are the tests. For the mineralization stage, the test case holds nitrogen mineralization fixed while temperature and moisture vary, and the augmented routine must move while the stock routine, whose organic phosphorus mineralization is proportional to nitrogen, cannot. For the transport stage, the test case is an event on a tile-drained soil in which particulate phosphorus must reach the tile through the macropore pathway, against the stock routine's dissolved-only tile flux. Each of these cases is also run, in the form that fits it, in the code that supplies its verified behaviour, so the augmented routine is never its own only witness.

## Order inside the programme

This branch runs last among the model examples, because its stages consume the results of the others: the speciation examples bound what the sorption core's equilibrium should respect, the Parsons example supplies the core's architecture, the BioRT-Flux-PIHM example supplies its field-scale test bed, and the RZWQM2-P example supplies the transport behaviour of the fifth stage. The synthesis step of the programme then reports the augmented routine beside the stock routines and beside every supplying code, per branch and per saturation class, with the spreads between branches stated as part of the result.
